# Samples: what the parsers read, and how to get a real one

**Status: every parser in this repository that reads hub output is `schema_unverified`.** There is exactly one: the screenshot reader behind `ingest_capture`
(`visualverify/domain/hubshot.py`). No real capture existed when it was written, so its input shape is an ASSUMPTION built from the MCP specification's image content block
and the field names other repositories in this suite guessed. Its answers carry `input_schema: schema_unverified`, and so does the README of every tool that uses it.

## What this server never does

It does not call the hub, Studio or Blender. Measuring a Studio screenshot is a two-step job done by YOU (or your agent) with the hub:

1. **Run the hub call.** Call the hub's `screen_capture` tool (the Roblox Studio tool; the hub lists it with its own prefix, for example `roblox_studio_screen_capture`; its argument names are
   not documented in anything read here, so take them from the tool's schema). Capture with the place OPEN in Studio that matches the project/place you will measure for.
2. **Save the full result, unedited, to disk.** Save exactly what the call returned (the whole JSON, or the image file if the hub gives you one) as
   `samples/hub/screen_capture.<short-label>.json` (or `.png`). That folder is for REAL captures; it is empty on purpose. Anything outside the folders listed in `projects.yaml`
   (`image_roots`), `VISUALVERIFY_ALLOWED_PATHS` or `samples/` is refused, so save it inside one of them.
3. **Ingest.** `ingest_capture(path=..., name=..., project_id=..., place_id=...)` (dry run shows what it would write; `dry_run=false` writes a PNG under the project's private
   workspace and returns `image_path`). Then measure `image_path` with any tool.

If the parser refuses a real capture it says which top-level keys it found. **Send that file (or just its key names) back and the parser should be fixed against it**; until then treat
every result as `schema_unverified`.

## What is here

- `synthetic/`: three hand-written stand-ins (an MCP-style image block, a bare `image` field, a raw PNG), generated by `scripts/make_samples.py`. They are LABELLED synthetic, were not captured
  from anything, and prove only that the parser reads the shapes it was written for. They say nothing about what the real hub returns.
- `hub/`: empty. Real captures go here (see above). Nothing in the tests depends on this folder having files.

A real capture of an empty baseplate would still be a trivial case: a rich place, a viewport with a UI overlay, or a different capture size remain unchecked until you save them too.
