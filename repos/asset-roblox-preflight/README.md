# asset-roblox-preflight

A preflight for **Blender exports headed to Roblox**. Point it at an exported file (GLB, glTF, OBJ, or an FBX plus a hub summary) and a target profile (`prop`, `tool`,
`character_accessory`, `terrain_piece`) and it reports what is wrong in plain terms: rule id, object, measured value, limit and a one-line fix. It catches bad
uploads before they cost time. Built so a capable AI agent (Claude Code, Codex CLI, Gemini CLI, Copilot, Cursor, ...) can drive it through MCP, with a CLI that exposes
the same functions.

**What it is:** a rule engine (`rules/*.yaml`) + real GLB/glTF/OBJ readers + exact geometry, UV, texture and rig measurements + a safe-fix script generator + per-project
profiles, overrides and feedback + an eval suite. **What it is not:** it never connects to Blender, Roblox Studio or Roblox, never edits an export, never uploads or
publishes. A ready asset is handed to `roblox_upload_plan` through the hub. Model weights never change; the model chooses and explains, the code measures.

> **Honest status.** Built and tested only on **synthetic fixtures generated by script** (`scripts/make_examples.py`). It has **never been run against real Blender
> exports, a live Blender, Roblox Studio, or a real upload.** **Every numeric limit is a DEFAULT chosen by this tool's author, not an official Roblox limit** (each is marked
> `verify_against_current_docs`). `ready_to_upload` means "no errors on those defaults", never "Roblox will accept it".

## guide-core was not available: the adapter

The build instructions call for a shared `guide-core` library (dryrun, feedback, retrieval, evals, mock, luau_safety, mcpkit, config, scope). **It does not exist yet and
its spec was not provided.** Instead the repo uses its vendored `preflight/core` behind **one thin module, `preflight/guide_adapter.py`**, which re-exports the
equivalents under those names (`dryrun`: Plan and Versioner; `feedback`; `retrieval`; `evals`; `mcpkit`; `config`: style and rubric; `scope`: path policy and `resolve_inside`;
`mock` and `luau_safety` are explicit placeholders because nothing here touches Luau). All other modules import shared machinery only through that file (a test enforces it), so
**swapping in the real guide-core means editing `preflight/guide_adapter.py` only.** The adapter also contains one documented workaround for the vendored core: it filters the
core's unscoped `record_run`/`get_style_brief`/... tools so the project-scoped versions of the same names can replace them.

## Capability matrix

| Capability | Status |
|---|---|
| GLB reader (JSON + binary chunks, accessors incl. sparse and normalised, indices, normals, UVs, materials, images, skins/joints/weights, animations, node transforms) | tested on synthetic GLBs |
| glTF reader (data-URI or external buffers and images, relative paths only) | tested on synthetic files |
| OBJ reader (+ MTL texture references, n-gon count) | tested on synthetic files |
| **FBX** | **header only** (flavour, version, size). Geometry, UVs, materials and rig are **not parsed**. Without a hub summary an FBX is `UPL_NOT_MEASURED` (error) and never ready |
| Hub summary JSON (`preflight-summary/1`, our own schema, see below) | tested on hand-written summaries; **the real `blender_get_objects_summary` / `asset_validate` output shapes were not available**, map them into this schema |
| Mesh checks: triangle budget, loose geometry, non-manifold edges, flipped/inside-out normals, n-gons (OBJ/summary only), scale range, bbox | tested, hand-computed expectations |
| Transform checks: applied scale/rotation, negative scale, origin placement, root offset, units suspect, axis | tested |
| Names: duplicates, spaces/odd characters, `.001` suffix, naming scheme from `style/` (a STARTER scheme) | tested |
| UVs: present, 0-1, overlap, texel-density spread, wasted space, zero-area (measured on a 128x128 raster) | tested |
| Materials/textures: count, missing/unsafe paths, format, power of two, oversize, colour-space and slot mistakes, channels | tested; pixel statistics are a heuristic |
| Rig (tool, character_accessory only): root, naming, bone count, **one-bone `spin` setup**, weights, clip names, frame rate | tested |
| Collision proxy: present, declared absent, missing, budget, bounds | tested |
| Upload risk: file size, texture memory estimate, flagged features | tested on defaults |
| Safe-fix Blender script generator, run against a **fake `bpy`** | tested; **never run in real Blender** |
| Projects, per-project profiles/overrides/feedback, isolation | tested |
| MCP stdio server | tested in memory and over a real stdio subprocess |
| Live Blender / Studio / Roblox upload | **not done, by design** |

## Quick start

```bash
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"                             # Python 3.10+
python scripts/make_examples.py                     # (re)build the synthetic examples
python -m preflight projects                        # the registered (synthetic) projects
python -m preflight report examples/assets/bad_too_many_tris.glb --project synthetic-sandbox --profile prop
python -m preflight inspect examples/assets/good_tool_drill.glb --project synthetic-sandbox
python -m preflight fix-script examples/assets/bad_spin_bone_name.glb --project synthetic-sandbox --profile tool
python -m preflight eval run --label mine && python -m preflight eval compare baseline mine
python -m pytest
```

`report` exits 1 when the result is FAIL. Every command needs `--project`.

## Output

Short on purpose. The first line is the verdict; then ranked findings; details only on request.

```
FAIL bad_too_many_tris [glb, prop, project synthetic-sandbox, place 1000000003]: 1 error(s), 1 warning(s), 0 info; ready_to_upload=NO
findings: [ {id, rule, severity, object, measured, limit, fix}, ... ]   (top 10 by severity; `omitted` says how many more)
```

`ready_to_upload` is true **only when no errors remain** (and only for the full `preflight_report`; the partial `check_*` tools never say it). When it is true the
report carries `handoff: roblox_upload_plan` with the file, project and place for the hub. `verbose=true` returns everything (facts, skipped rules, assumptions);
`explain_finding` returns the explanation, the effective limits with their verify flags, and the instance record.

## Inputs

* **Export file** (`path`): `.glb`, `.gltf`, `.obj`, `.fbx`, or a summary `.json`. Files must be inside the repo, `PREFLIGHT_ASSET_ROOT`, or `PREFLIGHT_ALLOWED_PATHS`.
* **Texture folder** (`texture_dir`): searched together with the export's own folder. Texture URIs must be relative; absolute or `..` paths are reported (`TEX_UNSAFE_PATH`), never read.
* **Hub summary** (`summary` inline or `summary_path`): schema `preflight-summary/1`, documented in `preflight/domain/summary.py` (objects with name, type, transform, dimensions, triangle and
  edge counts, UV statistics, materials with texture paths and colour space, armatures with bones, animations with frame rate). Numbers in a summary are **reported, not measured**; findings built from
  them say so. If a readable GLB/glTF/OBJ is given together with a summary, the file is measured and the summary ignored.
* **`project_id`** (required everywhere; `place_id` optional and only recorded for the upload hand-off) and **`profile`**.
* `collision_intent` (`auto|present|absent`), `limit_overrides` for one call, `apply_saved_overrides`.

## Projects

`projects.yaml` is the registry (id, alias, place_id, universe, profile file). **The three entries shipped are clearly synthetic examples**; replace them. A tool without a resolved
`project_id` refuses and lists what is known; an unknown `project_id`, or a `place_id` that does not match the registered one, is refused. The preflight does not need an open Studio place.
`projects/<project_id>/profiles.yaml` overrides profile limits, severities, disabled rules and the naming scheme, layered over `rules/profiles/*.yaml` and `style/style.yaml`.

Feedback (runs, decisions, corrections), library entries, overrides, saved reports and generated scripts are stored under `workspace/projects/<project_id>/`. Records marked
`global` (`global_scope` / `global_override`) go to `workspace/projects/global/` and are read by every project; nothing else crosses projects (tested). Every report names its project and place.

## Rules, profiles and limits

Everything the tool judges is a rule in `rules/*.yaml` (id, severity `error|warn|info`, explanation, one-line fix, `safe: true|false`, numeric limits each marked
`verify_against_current_docs`). The code only measures and compares; a test fails if a rule has no code or code has no rule. Profiles are in `rules/profiles/`. See `rules/README.md`.
Rig rules apply only to `tool` and `character_accessory`; a rig in a prop or terrain piece gets `RIG_UNEXPECTED`. The one-bone `spin` setup (drill tips): exactly one bone named `spin`, a direct
child of the root bone, with no child bones, owning its vertices at weight 1.0; a near-miss name (`Spin_Bone`) is the safe fix `rename_bone`.

## Safe fixes

`apply_safe_fix` only acts on rules marked `safe: true`: renaming objects/bones (invalid characters, `.001` suffixes, the spin bone, the root bone name) and applying scale/rotation on plain
(unskinned) mesh objects. It returns a plan (default `dry_run=true`) and the script text; with `dry_run=false` it writes the **script** under `workspace/projects/<id>/output/fixes/`. It never
edits an export, never saves or exports in Blender, and lints itself (only `bpy` and `json` imports). Give the script to the hub to run in Blender **on a copy**, re-export, and run `preflight_report` again.
Tested by running the script against a fake `bpy`; never run in real Blender.

## Tools

Read-only tools carry `readOnlyHint`; writing tools default to `dry_run=true` where they write a plan (the feedback tools, as in the other repos, write only when called).
All take `project_id`. **Rare group:** tools marked `[rare]` can be left disabled by a client, or removed from the server with `PREFLIGHT_DISABLE_RARE=1`.

## Learning

* **Overrides.** "This prop may be 30k tris": `record_override(project_id, rule="MESH_TRI_BUDGET", asset_type="prop", value=30000, reason=<their words>)`. It is scoped to the project and asset type, applied on later runs
  (and listed under `overrides_applied`), never applied to other projects unless `global_override=true`. A waiver (`waive=true`) keeps the finding visible as info.
* **Promotion.** After `3` repeats `record_override` and `preflight_report` offer to promote it; `suggest_profile_promotions` returns the exact patch for `projects/<id>/profiles.yaml` (or the global profile for global
  overrides). It never edits a profile: a person applies it and re-runs the evals.
* **Corrections.** `record_run` / `record_decision` / `find_past_corrections` / `promote_run` (shared core code, project-scoped). Nothing changes model weights.

## Token discipline

One-line summary first, ranked findings capped at 10 by default, details through `explain_finding`, concise tool descriptions (tested, longest 300 characters), a `rare` group,
and an eval task per tool with a character budget (`evals/tasks/token_budget.yaml`) so growth shows up as a failing task.

## Evals

`evals/tasks/*.yaml`: known-good assets that must pass cleanly, known-bad assets that must be caught, measurements with hand-computed values, safe-fix scripts, projects and isolation, overrides, output-size
budgets (157 tasks). `python -m preflight eval run --label X`, `eval compare baseline X`, `eval check-results DIR --label X` (score an agent's saved outputs). A test breaks rules on purpose and checks that tasks fail
(the vacuous-eval guard). `evals/rubric.yaml` is the report rubric.

## Connecting agents

Canonical: `AGENTS.md` and `skills/asset-roblox-preflight-workflow/SKILL.md`; `python scripts/sync_agent_files.py` copies them where clients look (a test checks drift). MCP configs for Claude Code,
Claude Desktop, Cursor, Gemini CLI, VS Code and Codex are in `adapters/mcp-clients/` (documented shapes, not tested against live clients). The server is local, stdio, unauthenticated.

## What you still have to supply

* **Your projects** (ids, place IDs, universes) in `projects.yaml`; the shipped ones are synthetic.
* **Your limits**: triangle, texture, bone, file-size numbers, verified against current Roblox documentation, in `rules/profiles/*.yaml` and `projects/<id>/profiles.yaml`.
* **Your naming scheme** in `style/style.yaml` (the shipped one is a labelled starter).
* **Pacing** is not used by this repo (it belongs to the economy balancer).
* **Real example files**: a good export and a bad export from your pipeline, to replace or add to the synthetic ones, and the real hub summary output to map into `preflight-summary/1`.

## Limitations

* Never run against real Blender exports, live Blender, Studio or Roblox. Synthetic fixtures only.
* FBX geometry is not parsed. n-gons cannot be measured from GLB.
* Compressed glTF (Draco, meshopt) is refused, not decoded. Sparse accessors are read; morph targets are only flagged.
* UV overlap and coverage are measured on a 128x128 raster; texel density uses area-weighted percentiles; the normal-map check is a pixel heuristic and a file-name guess.
* Animation frame rate in glTF is estimated from keyframe spacing.
* Units: 1 export unit = 1 stud is a default assumption (`studs_per_unit`), not verified.
* The `.001`-style and naming rules follow a starter scheme.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `project_id is required` / `unknown project_id` | Use `list_projects`; add the project to `projects.yaml` |
| `place_id ... does not match project` | Fix the place id or the registry |
| `outside the allowed directories` | Set `PREFLIGHT_ASSET_ROOT` or `PREFLIGHT_ALLOWED_PATHS` |
| `geometry is compressed with KHR_draco_mesh_compression` | Re-export without mesh compression |
| `UPL_NOT_MEASURED` | The input was an FBX without a summary; export a GLB or pass a summary |
| `rule X is not marked safe` | Fix it by hand using the finding's one-line fix |
